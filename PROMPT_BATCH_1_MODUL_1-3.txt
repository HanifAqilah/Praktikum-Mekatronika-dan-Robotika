PANDUAN JOBSHEET.MD (MODUL 1):

1. TUJUAN PRAKTIKUM
   - Tujuan umum: Mahasiswa dapat merancang arsitektur sistem robotika terintegrasi
   - Sub-tujuan:
     a. Desain blok diagram sistem (mechanical, electrical, software layer)
     b. Mapping signal & pin (sensor → controller → actuator)
     c. Analisis komunikasi protocol (MQTT, Modbus, CAN)
     d. FMEA basic untuk system failure

2. ALAT & BAHAN
   HARDWARE:
   - Mini robot atau chassis (AGV / arm 3-DOF / conveyor mini)
   - Motor DC + encoder (2-3 unit)
   - Sensor: limit switch, IR, distance sensor (minimal 3 jenis)
   - Mikrokontroler: Arduino Mega atau ESP32
   - Driver motor: L298N atau sejenisnya
   - Power supply 24V, 12V, 5V
   - Kabel, breadboard, jumper wire
   - Ubuntu PC (untuk ROS2 edge compute)
   
   SOFTWARE:
   - Fusion 360 (for CAD design)
   - EasyEDA (for schematic)
   - PlatformIO (VS Code extension)
   - ROS2 Humble
   - Python 3.10+
   - Git
   
   TOOLS:
   - Multimeter
   - Oscilloscope (optional, untuk verify signal)
   - USB adapter (untuk board programming)

3. LANGKAH KERJA
   
   PERCOBAAN 1: DESAIN BLOK DIAGRAM SISTEM
   Tujuan: Understand system architecture dengan membuat block diagram
   
   Langkah:
   a. Definisikan requirement sistem:
      - Input: user command (via web atau joystick)
      - Process: path planning, motion control, sensor fusion
      - Output: motor movement, telemetry data
   
   b. Identifikasi setiap komponen:
      - Mechanical: motor type, transmission, load
      - Electrical: power supply, driver, protection device
      - Software: embedded firmware, ROS2 node, web server
   
   c. Buat block diagram di tool (Visio, draw.io, atau Fusion 360):
      [User Command] → [Web Server] → [ROS2 Node] → [ESP32] → [Motor Driver] → [Motor]
      [Motor Encoder] → [ESP32] → [ROS2 Node] → [Web Dashboard]
   
   d. Anotasi: interface antara blok (protocol, signal type, frequency)
   
   e. Deliverable: Block diagram image (PNG/PDF), description text
   
   Data Pengamatan:
   | Komponen | Tipe | Fungsi | Interface | Pin/Protocol |
   |----------|------|--------|-----------|--------------|
   | Motor | DC | Actuator | PWM + DIR | GPIO 25, 26 |
   | Encoder | Incremental | Feedback | Digital | GPIO 27, 28 |
   | ...  | ... | ... | ... | ... |
   
   ---
   
   PERCOBAAN 2: PIN MAPPING & SIGNAL ROUTING
   Tujuan: Detailed mapping semua signal dari sensor ke controller ke actuator
   
   Langkah:
   a. Ambil hardware yang ada (motor, sensor, PCB)
   b. Identify setiap pin di mikrokontroler yang akan digunakan
   c. Create wiring diagram:
      - Gambar di EasyEDA atau draw manually dengan label lengkap
      - List semua koneksi: dari pin X ke komponen Y
   
   d. Create pin mapping table:
      | Signal | Component | Mikrokontroler Pin | Type | Purpose |
      |--------|-----------|-------------------|------|---------|
      | PWM_Motor | Motor Driver | GPIO 25 | PWM Output | Speed control |
      | DIR_Motor | Motor Driver | GPIO 26 | Digital Output | Direction |
      | ENC_A | Encoder | GPIO 27 | Digital Input | Speed feedback |
      | ...  | ... | ... | ... | ... |
   
   e. Deliverable: Wiring diagram + pin mapping table (dalam spreadsheet atau table format)
   
   Data Pengamatan:
   - Total digital pin used: __
   - Total analog pin used: __
   - Total PWM pin used: __
   - Spare pin available: __
   - Potential conflict: (e.g., I2C on same pin dengan SPI) __
   
   ---
   
   PERCOBAAN 3: COMMUNICATION PROTOCOL ANALYSIS
   Tujuan: Understand dan pilih protocol komunikasi yang sesuai untuk sistem
   
   Langkah:
   a. Research 3 protocol: MQTT, Modbus RTU, CAN Bus
   b. Untuk setiap protocol, isi table:
      | Parameter | MQTT | Modbus RTU | CAN Bus |
      |-----------|------|-----------|---------|
      | Topology | Publish-Subscribe | Master-Slave | Multi-master |
      | Latency | 50-200 ms | 10-100 ms | 1-10 ms |
      | Reliability | QoS adjustable | Checksum | CRC |
      | Bandwidth | Efficient | Low | High |
      | Complexity | Medium | Low | High |
      | Typical Use | IoT, Cloud | Industrial, PLC | Real-time control |
   
   c. Analisis requirement sistem:
      - Latency requirement: ____ ms
      - Real-time critical? Yes/No
      - Number of device: ____
      - Bandwidth need: ____ kbps
   
   d. Recommendation: Pilih 1 protocol yang paling sesuai, jelaskan alasan
   
   e. Deliverable: Comparison table + recommendation + justification
   
   ---
   
   PERCOBAAN 4: FMEA BASIC (FAILURE MODE & EFFECTS ANALYSIS)
   Tujuan: Identify potential failure dan mitigation strategy
   
   Langkah:
   a. Identifikasi potential failure point di sistem:
      - Mechanical: bearing fail, belt slip, gear tooth break
      - Electrical: power loss, wire break, short circuit
      - Software: firmware crash, communication loss, sensor timeout
   
   b. Untuk setiap failure, isi FMEA table:
      | Failure Mode | Component | Effect | Cause | Detection | Mitigation | Severity |
      |--------------|-----------|--------|-------|-----------|-----------|----------|
      | Motor not moving | Motor + Driver | Robot stuck | Power loss, firmware crash, driver damaged | Watchdog timer, current sensor | E-Stop, safe stop, fallback to manual | High |
      | Sensor loss | Encoder | Wrong position estimate | Cable disconnect, sensor damaged | Timeout + LED indicator | Use previous position, reduce speed | Medium |
      | ... | ... | ... | ... | ... | ... | ... |
   
   c. Severity rating: Low (1-3), Medium (4-6), High (7-9)
   
   d. Deliverable: FMEA table (Excel atau table format)

4. DATA PENGAMATAN
   - Block diagram image (dengan annotation)
   - Pin mapping table
   - Protocol comparison table
   - FMEA table dengan minimal 10 failure mode
   - Design reasoning document

5. ANALISIS
   PERTANYAAN ANALISIS:
   - Apa advantage & disadvantage dari centralized control vs distributed?
   - Protocol mana yang dipilih untuk sistem ini? Mengapa?
   - Apa failure mode paling critical? Bagaimana mitigasi?
   - Apakah current design memenuhi requirement? Jika tidak, apa yang perlu diubah?
   - Apakah ada trade-off dalam design? (e.g., complexity vs reliability)

6. KESIMPULAN

PANDUAN MATERI.MD (MODUL 2):

1. DEFINISI
   - Safety dalam robotika: mencegah injury ke human atau damage ke equipment
   - Standards: ISO/IEC 62061 (safety robot), IEC 61508 (safety system general)
   - E-Stop: emergency stop untuk human safety
   - Commissioning: proses verifikasi & validation sebelum production

2. KONSEP INTI
   - E-Stop circuit: hardwired E-Stop yang independent dari main control
   - Limit switch: prevent over-travel, mechanical protection
   - Interlock: prevent unsafe state (e.g., gripper not closed saat move)
   - Watchdog timer: detect firmware hang atau stuck loop
   - Timeout: detect communication loss atau sensor not responding
   - Safety layer vs Control layer: separation of concern
   - Safe state: apa state terendah yang aman saat fault (usually: stop all motor)
   - Diagnostics: identify root cause failure

3. DIAGRAM & ILUSTRASI
   - E-Stop circuit diagram (hardwired vs software triggered)
   - State machine diagram (idle → ready → running → fault → recovery)
   - Timing diagram: E-Stop press → motor stop (dalam berapa ms?)
   - Fault tree analysis (apa causes robot jadi unsafe)
   - Communication timeout example (sensor stop reporting → timeout → safe stop)
   - Limit switch position diagram (home position, joint limit, workspace boundary)

4. CONTOH KASUS INDUSTRI
   - ABB robot factory: E-Stop zones, safety fence, motion monitoring
   - Warehouse AGV: obstacle detection, emergency stop, safe docking
   - Medical robot: redundant safety system, sterilization procedures
   - Automotive manufacturing: interlock safety gates, dual-channel monitoring

5. RINGKASAN
   - Safety adalah responsibility bersama (mechanical, electrical, software)
   - Commissioning adalah mandatory sebelum operate, jangan skip
   - Fault handling harus graceful, jangan crash tanpa warning
   - Log & diagnostics penting untuk root cause analysis

6. DESKRIPSI TUGAS VIDEO (MODUL 2)
   Point yang HARUS dijelaskan:
   - E-Stop circuit: how it's hardwired independent from CPU
   - State machine: idle → running → fault → recovery
   - Limit switch: mechanical backup untuk software limit
   - Watchdog: how it detects firmware hang
   - Demo: press E-Stop → observe immediate motor stop (< 100ms)
   - Demo: trigger fault scenario → observe safe stop
   - Troubleshooting: common safety issue & solution

PANDUAN JOBSHEET.MD (MODUL 2):

1. TUJUAN PRAKTIKUM
   - Implementasi E-Stop system yang reliable
   - Test limit switch & homing procedure
   - Interlock logic implementation & verification
   - Watchdog & timeout detection
   - Fault state management & logging

2. ALAT & BAHAN

   - E-Stop button (hardwired type)
   - Limit switch (min 2 unit)
   - Relay module (untuk E-Stop circuit)
   - Current sensor atau ammeter

3. LANGKAH KERJA
   
   PERCOBAAN 1: E-STOP IMPLEMENTATION
   - Wire E-Stop button ke safety relay
   - Program microcontroller untuk detect E-Stop signal
   - Verify E-Stop work immediately (< 100ms response time)
   - Test multiple E-Stop activation (reliability test)
   
   Deliverable: Schematic, code, test result (response time measurement)
   
   PERCOBAAN 2: LIMIT SWITCH INTEGRATION
   - Install limit switch di joint limit position
   - Program software limit (tidak bergerak beyond limit)
   - Test mechanical limit & software limit together
   - Homing procedure: gerak ke home position, detect limit switch
   
   Deliverable: Position diagram, code, homing procedure SOP
   
   PERCOBAAN 3: STATE MACHINE IMPLEMENTATION
   - Design state: idle, ready, running, fault, recovery
   - Implement state transition logic
   - Test state change (manual command, timeout, E-Stop trigger)
   - Verify interlock (e.g., tidak bisa run jika gripper tidak closed)
   
   Deliverable: State diagram, code, state transition test log
   
   PERCOBAAN 4: WATCHDOG & TIMEOUT
   - Enable watchdog timer di microcontroller
   - Implement communication timeout (detect sensor loss > 100ms)
   - Test watchdog trigger (observe safe stop)
   - Test sensor loss (unplug encoder, observe timeout → safe stop)
   
   Deliverable: Code, timeout test result, watchdog configuration
   
   PERCOBAAN 5: FAULT DIAGNOSTICS
   - Program fault logging (timestamp, fault type, sensor value)
   - Implement fault recovery: attempt recovery, or goto safe state
   - Test fault scenario: motor stall, sensor timeout, power dip
   - Analyze fault log (root cause analysis)
   
   Deliverable: Fault log file (CSV or JSON), diagnostics code

4. DATA PENGAMATAN
   - E-Stop response time (ms)
   - Limit switch detection accuracy
   - State machine transition time
   - Watchdog trigger count
   - Fault recovery success rate
   - Downtime per fault type

5. ANALISIS
   - E-Stop response time vs requirement (< 100ms standard)
   - Fault detection reliability: true positive vs false positive
   - Recovery effectiveness: how many fault dapat auto-recover?
   - Recommendations untuk improvement

6. KESIMPULAN
   - Safety system yang reliable adalah critical untuk production
   - Proper commissioning prevent many issues
   - Log & monitoring essential untuk troubleshooting

PANDUAN MATERI.MD (MODUL 3):

1. DEFINISI
   - Power distribution: supply tenaga ke setiap subsystem dengan stable voltage
   - EMC: device tidak generate excessive noise & tidak susceptible terhadap external noise
   - Noise: unwanted signal (electro-magnetic interference dari motor, switching circuit)

2. KONSEP INTI
   - Power tree: hierarchical power supply (24V input → 12V reg → 5V reg → 3.3V reg)
   - Voltage drop: I × R loss, critical untuk long cable
   - Transient response: saat motor on/off, power draw berubah drastis
   - Capacitive decoupling: local capacitor dekat IC untuk smooth transient
   - Grounding: return path untuk current, critical untuk noise immunity
   - Star grounding: single point untuk low-frequency, plane untuk high-frequency
   - Shielding: Faraday cage untuk block EMI
   - Cable twist: 2 wire twist untuk cancel magnetic field

3. DIAGRAM & ILUSTRASI
   - Power tree block diagram (input → converter → output, dengan voltage ripple waveform)
   - Decoupling capacitor placement (dekat setiap IC pin)
   - Ground plane vs single wire ground (noise comparison)
   - Filter design: RC low-pass filter, LC filter (frequency response graph)
   - PCB layout: power plane, ground plane, signal routing
   - Noise spectrum (before filter vs after filter)
   - Cable routing: power cable vs signal cable separation

4. CONTOH KASUS INDUSTRI
   - Industrial servo drive: multi-stage power, careful grounding untuk analog signal
   - Automotive ECU: ripple requirement < 100mV, noise susceptibility test
   - Robot with high-speed motor: radio frequency noise dari switching, ferrite filter solution
   - Data center power: PFC (Power Factor Correction), UPS integration

5. RINGKASAN
   - Power integrity adalah foundation untuk reliable control
   - EMC design tidak bisa di-add setelah, harus dari design awal
   - Measurement important untuk verify design

6. DESKRIPSI TUGAS VIDEO (MODUL 3)
   Point yang HARUS dijelaskan:
   - Power tree: kenapa multi-stage regulator?
   - Noise source: motor switching, converter switching
   - Decoupling capacitor: kenapa dekat IC?
   - Ground plane vs ground wire: difference & why plane better?
   - Filter design: RC vs LC, trade-off response time vs attenuation
   - Demo: measure voltage ripple with/without filter (oscilloscope)
   - Demo: motor on/off, observe power transient (before/after capacitor)
   - PCB layout best practice
   - Troubleshooting: common power/EMC issue (sensor noise, unstable voltage)

PANDUAN JOBSHEET.MD (MODUL 3):

1. TUJUAN PRAKTIKUM
   - Design & implement power distribution system
   - Measure & analyze noise in system
   - Design & implement filter
   - Verify power integrity & EMC

2. ALAT & BAHAN
   - Power supply multi-output (24V, 12V, 5V)
   - Voltage regulator: LM7805 (5V), LM7812 (12V), atau switching regulator
   - Capacitor: electrolytic (bulk), ceramic (decoupling)
   - Inductor (for LC filter)
   - Resistor (for RC filter)
   - Oscilloscope (untuk measure ripple & transient)
   - Load: motor + resistor untuk simulate load change
   - PCB (prototype PCB atau breadboard)

3. LANGKAH KERJA
   
   PERCOBAAN 1: POWER TREE DESIGN
   - Analyze requirement (voltage, current per subsystem)
   - Design regulator circuit: input → 24V → 12V → 5V → 3.3V
   - Calculate capacitor value (bulk + decoupling)
   - Build circuit on breadboard atau PCB
   
   Deliverable: Schematic, BOM, power tree diagram, assembled circuit
   
   PERCOBAAN 2: NOISE MEASUREMENT (BASELINE)
   - Setup oscilloscope to measure voltage at each regulator output
   - Measure voltage ripple (peak-to-peak, frequency)
   - Measure response saat load on/off (transient response time)
   - Record data: voltage vs time graph
   
   Deliverable: Oscilloscope screenshot, measurement data (CSV)
   
   PERCOBAAN 3: FILTER DESIGN
   - Design RC low-pass filter untuk motor noise: fc = 10kHz
   - Design LC filter untuk EMI suppression
   - Calculate component value (R, C, L)
   - Build filter circuit
   
   Deliverable: Filter schematic, component calculation, filter circuit built
   
   PERCOBAAN 4: NOISE MEASUREMENT (AFTER FILTER)
   - Repeat measurement dengan filter installed
   - Compare ripple amplitude
   - Compare response time (faster atau slower?)
   - Analyze trade-off
   
   Deliverable: Before/after graph, comparison table
   
   PERCOBAAN 5: STABILITY TEST
   - Load test: apply different load (0% → 25% → 50% → 100%)
   - Measure voltage regulation (voltage change at full load vs no load)
   - Transient test: sudden load change, measure droop & recovery time
   
   Deliverable: Load regulation graph, transient response measurement

4. DATA PENGAMATAN
   - Voltage ripple (mV peak-to-peak, frequency)
   - Transient response (droop amplitude, recovery time)
   - Noise frequency spectrum (FFT analysis)
   - Load regulation (ΔV at 100% load)
   - Filter attenuation (dB)

5. ANALISIS
   - Power ripple memenuhi requirement? (typical < 100mV untuk analog, < 200mV untuk digital)
   - Transient response acceptable? (rise time, overshoot)
   - Filter effectiveness: berapa dB attenuation?
   - Trade-off: filtering yang lebih baik vs response time lambat?
   - Recommendation: upgrade ke switching regulator? Better grounding plane?

6. KESIMPULAN
   - Power integrity critical untuk noise-sensitive application
   - Proper filtering improve system reliability
   - Measurement verify design effectiveness
